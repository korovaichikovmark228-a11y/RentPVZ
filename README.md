# Рядом.Аренda — лендинг для теста гипотезы

Fake-door лендинг: проверяем, готовы ли люди брать вещи в аренду в ближайшем
пункте выдачи (Ozon / Яндекс Маркет / Wildberries).

Человек выбирает вещь → «Забронировать» → показывается «техническая ошибка» →
его просят оставить телефон. Так мы меряем и намерение (клик по брони), и
реальную готовность (оставленный контакт).

## Стек
- Next.js 14 (App Router), React 18 — статичный лендинг + один API-роут.
- Vercel Web Analytics — заходы, устройства, источники + кастомные события воронки.
- Telegram-бот — доставка заявок (телефон/имя/район).

## Аналитика (воронка)
Кастомные события уходят в Vercel Web Analytics → вкладка **Events**:

| Событие | Когда |
|---|---|
| `hero_cta`, `nav_cta`, `final_cta` | клики по призывам |
| `open_booking` | открыл окно брони (props: item, source) |
| `confirm_booking` | нажал «Забронировать» (props: item, days, total) — сильный сигнал |
| `error_shown` | увидел «техническую ошибку» |
| `lead_submitted` | оставил телефон — **целевое действие** |
| `close_modal` | закрыл окно (props: item, step) |

Заходы на сайт и источники трафика — на главной вкладке Web Analytics.

## Переменные окружения
Скопируйте `.env.example` → `.env.local` и заполните (см. комментарии внутри):

```
TELEGRAM_BOT_TOKEN=...
TELEGRAM_CHAT_ID=...
```

На Vercel те же две переменные задаются в **Settings → Environment Variables**.
Если они не заданы — заявка не теряется (логируется), но в Telegram не придёт.

## Локальный запуск
```bash
npm install
npm run dev
# http://localhost:3000
```

## Деплой
Пуш в GitHub → импорт репозитория в Vercel → задать 2 переменные окружения →
включить Web Analytics (вкладка Analytics в проекте).
